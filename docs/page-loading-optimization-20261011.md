# 首屏与页面加载优化（2026-10-11）

## 实施范围

- 移除站点配置对整个路由树的阻塞。站点设置仍由 React Query 请求和共享，品牌色、图标异步同步，不影响权限与接口契约。
- 修复并行启动暴露的缓存竞态：未登录确认或身份切换只清理私有查询，保留显式白名单内的匿名应用目录、文章、文档及站点设置查询，避免取消公开请求后页面一直加载。
- 当前路由匹配后，并行预加载其 Provider、布局和页面代码。导入 Promise 复用；未匹配页面不会因此全量预加载。预加载只执行模块导入，不渲染受保护组件，不代替身份校验。
- 首屏统一采用布局占位：后台 240px 侧栏、64px 顶栏和内容骨架；手机隐藏侧栏。前台采用导航、内容和页脚占位。
- 权限校验仍先于受保护菜单和页面渲染；客户导航在身份确认期间显示账户占位，避免先闪出登录按钮。
- 页面内部 Suspense 保留原有框架，只切换内容骨架；前台按列表/详情/通用页面展示不同结构，后台 AsyncState 使用 Ant Design Skeleton。
- 内容骨架保留空间并延迟 160ms 显现，减少快速请求的闪动；适配明暗主题和减少动态效果偏好。
- 应用详情的数据加载也使用双栏骨架；首次模块加载失败提供重新加载入口，既有接口错误重试保留。

## 验证重点

新增浏览器回归验证：配置请求未完成时公开内容仍可用；身份校验未完成时后台菜单和内容不可见；认证成功后可进入后台；当前分支导入并行且去重，其他页面不提前导入，预加载失败不产生未处理的 Promise 拒绝。

继续验证 22 个后台路由、15 个公共页面的依赖边界，确保公共入口不引入 Ant Design、Radix 或 Sonner 等路由专用依赖。

## 边界

这次调整首屏和路由启动流程，不改订单、支付、部署和权限协议。并非 SSR，首次 HTML 到 JavaScript 启动之前的网络等待仍然存在；慢接口也不会凭骨架自动变快。已有筛选与提交逻辑保持页面局部处理，没有统一重写所有业务页面的数据刷新策略。
