# 微信支付 V3 升级

实现参照 Retail 的 Native 扫码支付提供者，以及 Edu 的 V3 请求签名、响应验签和通知处理。Stack 保留自身订单、权益、托管订单项、退款及幂等事务。

- 下单：`POST /v3/pay/transactions/native`，JSON 金额使用整数分。
- 查单、关单：V3 商户订单号接口。未知交易状态拒绝自动推断完成。
- 通知：原始报文 RSA 验签、公钥 ID/证书序列号匹配、五分钟时间窗口、AES-256-GCM 解密，核对商户、AppID、币种。业务层核对订单与金额并幂等发放权益。成功返回 HTTP 204，处理失败返回 500 以便重试。
- 退款：沿用既有独立退款单号、部分退款、异步查单和金额校验，补充密钥 ID 校验。请求禁止重定向。
- 后台：配置 API v3 密钥、商户 API 私钥、商户证书序列号、微信支付公钥及其 ID（也可填写平台证书及其序列号）。敏感值加密存储，只返回配置状态，留空保留原值。

## 后台与 Edu 对齐（2026-10-09）

后台「支付配置 → 微信支付」按 Edu 的顺序提供九项设置：启用微信支付、支付应用标识、微信支付商户号、商户接口证书序列号、商户接口证书私钥、第三版支付接口密钥、微信支付公钥标识、微信支付公钥、支付回调地址。Stack 使用 Native 扫码支付，AppID 的说明据此调整，不复制 Edu 的小程序专属描述。

私钥和公钥通过本地 PEM 文件选择器读取，不上传对象存储，不在页面回显原文；只显示文件名和配置状态。文件扩展名、20KB 大小上限及 PEM 格式在浏览器检查，服务端进一步检查 RSA 2048 位或以上私钥/公钥类型。APIv3 密钥使用密码输入，须为 32 位 ASCII 字符。所有敏感配置沿用加密存储。

编辑后显示待保存项数和字段标记，统一点击「保存微信支付设置」。只发送修改项，未修改时不能保存；请求进行中禁用编辑，失败及支付标签切换时保留草稿，成功清除敏感草稿。读取失败先提供重试；无管理权限时禁用编辑。清除本组后台配置需要确认，成功后丢弃未保存修改。

启用开关实际控制新支付入口；关闭后保留已有订单的通知、查单、关单、退款及退款查单能力。新建后台配置默认关闭；旧配置未设置开关时保持原行为。配置完整状态与启用状态分别显示，参数不完整时始终不能创建支付。

旧版曾忽略数据库中的回调地址；历史 HTTP/无效地址读取时继续按自动地址处理，不修改原始记录，也不让旧 IP 地址重新生效。支付回调地址可以填写公网 HTTPS URL，留空时由 `PUBLIC_BASE_URL` 自动生成 `/v1/billing/providers/wechat/notify`。浏览器、接口和配置注册表共用校验契约。部分配置可逐次补全，后续保存不会丢失先前保存的密钥；并发保存继续受版本校验和事务审计保护。

Stack 保持现有「后台数据库配置优先于环境变量」规则；清除后台配置会恢复环境变量回退。若只需停止新支付，应关闭启用开关并保存，而不是清除配置。

自动验证包含：文件上传/格式与大小拒绝/同文件重选、失败重试、敏感草稿清除、后台刷新、只读权限、读取重试、清除确认；数据库部分配置累积、加密与不回显、回调落地、无效变更原子性及并发保护；关闭后新支付被拒绝，已有订单通知、查单、关单和退款仍可完成。桌面与手机实际浏览器检查已完成。真实商户参数及实际资金验收仍由商户配置后进行。
