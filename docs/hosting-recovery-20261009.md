# 跨节点冷快照隔离恢复交付

## 结论

本批补齐了标准冷快照在另一台服务器上的隔离恢复与验真，尚未完成生产实例跨节点接管和公网切流。代码已推送，最终代码提交为 `de47513b9c5d710565a223bdf61e17fc869b8a1f`；发布验收状态见文末。

## 已实施

- 固定 Restic 快照 ID、部署标签及路径；依照独立保存的摘要下载和验证，不使用不稳定的 `latest`。
- 验证冷快照归属、可信适配器、镜像摘要、文件清单、归档路径/链接和容量。
- 在与现有实例及备份分开的目录中恢复到专用卷，逐文件比较内容、所有者、权限及链接关系。
- 冻结恢复计划；成功重试重新核对数据；中断时保留现场，要求清理后使用新操作 ID。
- 创建卷前后均核对归属，拒绝覆盖已有卷；清理前检查全部卷，拒绝删除仍被容器使用的数据。
- 新增 CI 的真实 PostgreSQL + Restic 恢复演练，并修复已有冷备份测试的 PostgreSQL 初始化就绪竞态。
- 两台节点按版本安装运维 CLI；生产 agent 配置和调度资格保持原状。

## 验证结果

真实演练路径：118.25.36.15 创建独立测试数据库和冷快照 → 独立 Restic 加密仓库 → 传输加密仓库至 82.157.22.93 → 固定快照下载 → 隔离卷还原 → 独立 PostgreSQL 校验 → 清理。

- 数据库 50 条记录、金额合计 16575、中文字段及持久文件一致。
- 约 40MB 冷快照的卷恢复与逐文件校验耗时 4.026 秒；此数字不含跨主机传输、数据库验证、应用启动及域名切换，不是整机 RTO。
- 快照损坏、冻结计划改写、中断恢复、外来卷和在用卷保护通过；测试容器、卷、临时仓库和测试密码已清理。
- 跨主机演练使用 `8f431c4` 工具版本；最终版本增加目录隔离与并发创建卷的归属复核，由新增 CI 回归验证。
- 原计划访问生产备份仓库的测试操作被自动审批拒绝，原因是可能触发保留清理。已改为独立仓库完成替代验证，没有使用生产备份仓库。

## 尚未完成

1. 本工具只支持停服/升级产生的 `lingcoo-cold-volumes-v1`；日常逻辑备份仍需通用恢复适配。
2. 源节点防双写隔离、双节点资源预留、目标应用接管与业务探针。
3. 默认域名及自定义域名切换、DNS 生效窗口和接管后的回退规则。
4. 整机损毁后的恢复顺序、RPO/RTO 验收；目标开始写入后禁止盲目回到旧数据。

因此，第五阶段已从“单节点升级/回退”推进到“异机数据恢复可验证”，不能标记为整机灾备和自动切流全部完成。现有 Retail、Edu 未作为故障演练对象。
