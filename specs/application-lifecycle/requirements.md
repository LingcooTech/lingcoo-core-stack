# 应用全生命周期管理

用户已授权自动实施、验证、提交推送和逐阶段继续。公开/私有与免费/收费相互独立；现有客户实例不因导入或新版本发布自动变化。

1. 当管理员选择公开或已授权私有 GitHub 仓库时，系统应从固定提交读取应用定义，展示预览并创建草稿；不得执行源码或覆盖同 Code 的既有应用。
2. 当开发者提供 JSON/YAML 应用定义时，系统应以同一契约校验应用信息、权益、镜像仓库、Compose 与生命周期；导入不包含明文密钥或强制公开安装仓库。
3. 当 CI 提交版本时，系统应验证应用范围、固定提交、镜像摘要与配置快照；重试相同版本应幂等，不允许更改已登记版本内容。
4. 当管理员发布版本时，系统应保存验证结果和审计记录；源码同步、构建成功、交付版本发布、商品上架、实例升级是不同操作。
5. 当用户获取免费应用时，系统应无需支付发放部署资格；托管独立计费。收费应用保留现有支付授权流程。
6. 当执行部署时，自有服务器和托管使用同一版本交付计划；执行器应隔离项目和持久数据，验证镜像、健康、初始化、备份与恢复。
7. 当管理员操作生命周期页面时，系统应显示仓库、提交、构建、镜像和实例引用关系；凭证只显示配置状态，且支持密钥轮换。

验收样本：Retail、Edu 和免部署扩展；新增通用样本证明协议不依赖其业务名称。外部凭证和真实支付未验证时必须明确标记。
