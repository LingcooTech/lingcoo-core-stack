# 发布配置检查

## 目标与范围

把应用启用前的配置门槛接入后台 API 与产品导入命令。检查正式售价、有效套餐与权益、标准交付清单、平台必填参数及密钥存在性、资源引用、固定镜像 digest；声明托管的应用还需运行与备份清单。

后台新建应用默认草稿。新应用启用、停用后重新启用，以及普通应用首次改为一键交付时，在应用/权益/报价事务内检查，失败整体回滚。管理员应先保存草稿、配置交付，再启用。已有启用的一键交付应用保留兼容，编辑不触发强制下架；其配置缺口仍通过报告显示。此兼容不是对旧版本的验收背书。

产品导入在声明 active + one_click 时自动执行严格验证并要求凭据，不能通过省略 `--ready-for-sale` 或跳过交付设置规避；目录和凭据落库后，在同一事务内执行同一个配置门槛。草稿导入仍可用于准备配置。dry-run 只表示离线检查，不能替代落库后的检查。

## 边界

- 管理报告只允许 apps.manage，展示检查结论，不返回凭据或配置值。
- 配置检查通过与正式上线验收分开。镜像在线拉取、仓库只读权限、实际交付/恢复、真实支付退款始终显式标记待在线验收，本阶段没有自动宣称这些通过。
- 不能靠配置值判断仓库令牌是否拥有写权限。下一步仍需专用只读令牌与干净环境拉取证据。
- 当前面向付费一键交付应用，零价或验收用途报价保留草稿。未来免费分发需独立权益发放政策。
- 此阶段不修改生产报价、现有部署服务期或真实支付状态。

## 验收

验证草稿可保存、缺少凭据/浮动标签/验收价格/失效权益不能发布，失败事务无部分更新；有效配置可启用但在线证据仍待验；普通用户不能访问检查报告；前端只读检查不自动发布。
