# Web 客户端 UI 优化（2026-10-11）

## 范围与技术选择

保留 React、Vite、Tailwind、Radix 和现有接口契约。管理后台继续使用 Ant Design；客户 Web 不引入 Ant Design，不迁移支付、授权或部署协议。

## 本次修复

- 购买弹窗限制在动态视口内，固定标题、滚动内容，保留屏幕边距；通用弹窗和抽屉统一高度限制、滚动和中文关闭标签。
- 修正应用详情、购买摘要、文章目录、页脚和应用支持页中无效的双栏 CSS。
- 账户与部署标签支持窄屏换行；应用详情使用 Radix Tabs，FAQ 使用 Accordion；套餐卡支持 Enter/空格操作。
- 应用列表、详情、文章、文档、订单、通知、已购应用、工单和部署列表区分接口故障与空数据，并提供重试。详情仅在确认 404 时显示内容不可用。
- 授权查询失败时提供恢复入口，避免误导为未购买。
- 列表与详情共用无在售套餐时的可用状态判定；仅有默认免费元数据、没有实际入口的应用显示“即将开放”。详情隐藏未填写的资料并合并重复更新时间。
- 头部、页脚、文档品牌图共用尺寸稳定的加载失败兜底；提高客户界面的次要文字对比度。
- 客户主要路由设置页面标题与 description，文章与文档使用各自摘要；修正文档嵌套 main 和移动目录标题。
- 购买组件按点击延迟加载，保持管理后台与客户 UI 的加载边界。

## 回归重点

新增浏览器测试覆盖：390×667 的购买下一步可正常点击、桌面详情真实双栏、账户五个标签不超出容器、列表失败后的重试恢复、详情 503 与 404 的区别、键盘切换标签及展开 FAQ、品牌图失败兜底。

保留原有组合计费测试，确认前端仍只提交套餐标识及版本，不自行决定支付金额。发布前运行代码检查与完整浏览器回归；CI 继续执行数据库集成、端到端和依赖审计。

## 边界与后续

- 本轮不自动改动生产应用内容、套餐价格或存储里的 Logo URL；代码兜底不等于修复远端图片服务。
- title/description 属于客户端路由元数据，不等于 SSR、预渲染或完整搜索引擎优化。
- 大型业务组件的进一步拆分可按具体业务变更推进；本轮先提取错误状态、品牌图、元数据及可用状态规则，避免为缩短行数重写支付与部署状态机。
- 静态截图和单次加载体积不能代表真实用户性能分位数，后续按实际流量建立性能基线。
