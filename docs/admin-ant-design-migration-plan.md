# Stack 管理后台 Ant Design 迁移与 Edu 对齐方案

Stack 管理后台统一迁移到 Ant Design，并参照 Edu 的页面容器、工具栏、表单、详情抽屉和状态反馈组织界面。迁移目标是减少基础控件和样式的自行维护，使后续新增后台功能可以直接复用稳定的页面模板。

本轮交付为整体方案。实施按下列阶段推进，阶段完成以功能、视觉和工程检查共同通过为准，安装依赖或局部替换控件不构成迁移完成。

## 迁移范围

截至 2026 年 10 月 10 日，`admin-ui/src/App.tsx` 中有 17 个后台业务区、21 条受业务区权限保护的页面路由，另有 `/admin/login`，共 22 条页面路由。三个历史重定向入口 `/admin/catalog`、`/admin/delivery`、`/admin/operations` 保持兼容。

| 范围                                    | 本轮安排                                  |
| --------------------------------------- | ----------------------------------------- |
| 后台登录、侧栏、顶栏、搜索、主题切换    | 迁移到 Ant Design，保留现有登录与权限行为 |
| 主内容区全部后台页面及嵌套弹窗、抽屉    | 完整迁移，并按 Edu 的页面组织规则优化     |
| 客户应用中心、账户中心、购买与部署门户  | 保留现有界面，纳入共享依赖和业务回归检查  |
| 公共内容页、文档站                      | 保留现有界面，验证全局样式和路由不受影响  |
| API、授权、支付、部署、托管任务、数据库 | 复用现有实现与接口契约                    |
| 富文本、Markdown、代码高亮等专用组件    | 保留适用的成熟组件，统一外围布局和主题    |

后台、客户门户和文档站目前同属一个 Vite 工程。后台迁移完成后，整个工程仍可能保留 Radix、Tailwind、Sonner、React Hook Form 等门户所需依赖；是否删除取决于实际使用情况。后台运行路径应消除对旧基础 UI 和旧表单体系的依赖。

## 技术方案

### 依赖与版本

采用 Ant Design 6 和对应的 `@ant-design/icons` 6。Edu 当前直接依赖版本为 `antd@6.6.2`、`@ant-design/icons@6.3.2`，实施时以这组版本为兼容基线，检查发布状态、依赖审计和构建结果后锁定精确版本及 lockfile；补丁升级集中进行。

Stack 当前声明 React 19.1 系列，满足 Ant Design 6 的 React 18 及以上要求。沿用 Stack 的 React、Vite、路由、TanStack Query 和工具链，不把 Edu 的 Node、包管理器或整个前端工程一并迁入。

使用标准 Ant Design 组件及少量页面组合组件。当前不引入 Ant Design Pro、Umi 或 ProComponents；现有路由、权限和请求管理已能承担对应职责。

### 后台 Provider 与主题

在后台路由边界和后台登录页接入 `AdminUiProvider`，组织 `ConfigProvider` 与 Ant Design `App`，配置中文语言、品牌主色、字号、圆角及明暗主题。Provider 必须在后台路由懒加载边界内可用，并覆盖路由异常、确认弹窗、消息和通知。

继续使用 Stack 现有 `light / dark / system` 主题选择和后台品牌配置，将其映射为 Ant Design token。品牌主色变化不能只更新旧 CSS 变量；Ant Design 组件、链接和状态反馈也必须同步。

后台消息和确认框统一使用 `App.useApp()` 获得的上下文实例。业务请求模块返回结果或抛出类型化错误，反馈由页面或业务 Hook 处理，避免在模块初始化时绑定全局消息实例。

Tailwind 4 与 Ant Design 共存期间，按照官方兼容指引明确 CSS layer 顺序，例如 `theme, base, antd, components, utilities`。根据选定配置显式管理 reset 所在层。后台新增样式使用命名空间和语义类，避免通配选择器、全局 reset 和大量针对 Ant Design 内部 DOM 的覆盖。弹窗通过 portal 挂载时也必须获得正确主题和样式。

首批使用标准运行时样式机制，静态样式提取等构建优化留待实际构建体积和加载测量后决定。门户样式不因换库整体重写。

### 组件边界

建议在现有工程内建立 `components/admin` 和 `styles/admin.css`，沿用现有 `api`、contracts、鉴权及权限定义，避免为换库新增独立前端工程或复制服务端业务。

| 层级                                                      | 职责                                       |
| --------------------------------------------------------- | ------------------------------------------ |
| `AdminUiProvider`、后台 Shell                             | 主题、消息上下文、导航、标题、布局和响应式 |
| `PageContainer`、`PageToolbar`、`PageActions`、`PageHelp` | 页面容器、筛选与操作位置、使用说明         |
| `ManagementDrawer`、`FormActions`、`AsyncState`           | 详情和编辑容器、提交区域、异步状态         |
| `StatusTag`、展示格式函数、业务 Hook                      | 状态语义、金额时间展示、业务请求与交互状态 |
| 业务页面                                                  | 字段、列、业务分组、可执行操作及权限判断   |

基础 Button、Input、Select、Table、Form 等直接使用 Ant Design。共享封装仅承担统一页面结构或实际重复的业务职责，避免把旧 Radix API 完整模拟到 Ant Design 上。

共享组件必须区分使用端。典型情况包括后台和账户中心共用状态展示，后台托管实例管理又引用客户退出服务面板。实施前建立静态与动态导入关系清单，将 API、校验、状态文案等非视觉逻辑提取复用，分别组织后台与门户视图。不能通过替换旧 `components/ui/button.tsx` 等全局入口来完成迁移。

临时适配器如确有必要，必须登记调用方、所属阶段和删除条件；最终后台不依赖这类适配器。仅为保留门户所需的旧组件不属于后台迁移残留。

### 表单与表格

后台表单最终统一为 Ant Design Form。Zod 和 contracts 保留为业务校验及提交边界，UI 校验规则调用对应字段或分组校验，避免维护两套不一致的业务约束。同一表单只有一个字段状态来源，不同时由 React Hook Form 和 Ant Design Form 管理。

迁移时按完整表单处理初值、异步回填、字段联动、数组字段、未保存变更、切换分组、弹窗重开、保存失败及后端字段错误。跨字段校验与服务端错误必须映射到实际字段；密钥留空保留原值、证书导入、清除配置和版本冲突遵循现有接口语义。

后台表格统一使用 Ant Design Table。保留原有服务端分页、排序和筛选参数及 URL 查询条件；表格组件不擅自改变数据加载方式。选择状态使用稳定业务 ID，明确全选仅覆盖当前页还是整个结果集，切换筛选时清除或提示已选择范围。未提供分页或排序 API 的页面维持真实能力，不在 UI 中展示无效入口。

## Edu 对齐规则

借鉴 Edu 的 `app/providers.tsx`、`layouts/AdminShell.tsx`、`PageContainer.tsx`、`ManagementDrawer.tsx`、`AsyncState.tsx`、`PageHelp.tsx` 和 settings 页面。提取适合 Stack 的规则与小型通用实现，不整体复制 Edu 的教育业务导航、工作范围和整份样式文件。

| 内容     | Stack 的统一规则                                                                  |
| -------- | --------------------------------------------------------------------------------- |
| 页面标题 | 顶栏显示当前位置和页面标题；主区仅在展示具体对象时补充对象标题、状态和操作        |
| 页面宽度 | 默认容器参照 Edu 的 1440px 上限；配置表单采用较窄档位，密集运维表格提供宽档位     |
| 工具栏   | 搜索筛选在左，页面动作在右；使用说明按需展开；批量动作只在选中后出现              |
| 内容结构 | 列表页、配置页、复杂编辑页、运维页各有模板；卡片对应有意义的业务分组              |
| 表单     | 标签、必填、来源、敏感标记、说明和错误位置一致；短字段双列，长文本和证书单列      |
| 按钮     | 一个操作区域通常只有一个主操作；辅助动作用默认或文本样式；危险动作明确标识并确认  |
| 提交区   | 取消在前、提交在后；统一 loading、防重复提交与脏状态提示；长表单操作区保持可见    |
| 详情容器 | 简单操作用 Modal；中等详情或编辑用 Drawer；复杂编辑用独立页面                     |
| 抽屉尺寸 | 参照 Edu 的 560、840、1080px 三档，并限制为可用视口宽度；正文滚动，操作区保持可见 |
| 状态反馈 | 加载、失败重试、无数据、无匹配和无权限分别表达；错误状态不能伪装成暂无数据        |
| 表格展示 | 主次信息清楚，状态使用语义颜色，金额时间格式统一；常用操作直接展示，其余放更多    |
| 小屏     | 筛选与操作可换行，表格只在自身区域横向滚动，活动标签可见，弹窗不超出视口          |

配置页保持已确认的 SMTP、S3、微信支付字段和顺序。参照 Edu 优化外观与交互时，Stack 原有配置生效优先级、加密和清除语义保持准确，不复制 Edu 不同的运行时行为。

## 实施阶段

### 阶段零 建立基线与迁移台账

盘点全部后台页面、嵌套控件、共享组件及其门户调用方。记录关键任务、权限矩阵、接口请求、当前 UI 截图及生产构建的入口和后台懒加载资源体积。标注每页负责人、阶段、状态和验收证据；执行现有工程检查，区分既有问题与迁移问题。

交付：页面与依赖清单、关键场景基线、迁移台账。此阶段不改业务界面。

### 阶段一 接入 Ant Design 与统一后台框架

安装锁定依赖；完成 Provider、主题和品牌同步、中文配置、消息上下文及 CSS 兼容；迁移后台登录、侧栏、顶栏、全局搜索和移动端导航。建立 Edu 式页面容器、工具栏、帮助、状态反馈、表单操作区和管理抽屉，并在 Storybook 中提供代表示例。

交付：可运行的后台框架和共享模板。验收登录与权限拦截、路由深链、搜索快捷键、主题切换、弹窗上下文、门户和文档站样式。

### 阶段二 迁移列表与详情页面

先以订单和用户页验证列表、筛选、分页、批量选择和详情模板，再覆盖授权、客户端安装、应用部署、通知、工单和事件日志。应用列表、内容列表随其编辑模块在阶段四收尾。

交付：上述业务区的完整 Ant Design 页面及嵌套弹窗。验收服务端查询参数、返回列表的条件保留、批量操作范围、行操作权限和失败反馈；在预览环境执行退款等写入场景。

### 阶段三 迁移系统配置和支付表单

完整迁移系统设置、支付配置和密钥管理。先完成 SMTP、S3、微信支付三个代表表单，再覆盖品牌、公共页面、内容导入、AI 和其他支付配置。分组保存、未保存提醒、来源标记、密码显隐、证书上传、连接测试和密文轮换保持一致。

交付：后台配置表单统一为 Ant Design Form。验收空值、默认值、敏感字段保留、部分失败、异步回填和配置冲突；连接检测与真正发送或支付行为区分。未配置生产支付凭据时，不将模拟回调验收表述为真实支付成功。

### 阶段四 迁移应用内容与素材编辑

完成应用列表和编辑、内容列表和编辑、文档管理、云存储及各处素材选择器。复杂表单使用 Form.List 等成熟能力处理动态条目，保留业务校验。列表、详情与编辑的路由和保存范围保持明确。

交付：接入发布、售卖授权配置、内容文档编辑与素材管理完整迁移。验收 Retail、Edu 两个应用的配置展示与修改，价格套餐、发布版本、图片选择、附件权限、文件替换和历史链接语义。

### 阶段五 迁移托管运维并完成主区优化

完整迁移托管服务器、实例、运维任务、告警、托管套餐以及相关退出、交接和恢复操作，完成仪表盘。主视图突出资源余量、健康、备份、服务期限和下一步动作；容器清单、原始上报和执行日志进入详情。对后台引用的客户视图完成边界拆分。

交付：后台全部业务区完成 Ant Design 迁移。验收两台现有服务器的只读监测和数据一致性；重启、恢复、升级、停机等写入验收使用隔离测试实例，不能以存量生产业务作为破坏性试验对象。

### 阶段六 清理依赖与整体验收上线

清除后台旧组件、旧样式、临时适配器和旧表单依赖路径；移除整个工程确已无人使用的依赖。同步 Storybook、测试 Provider、测试定位方式和后台架构文档。新增约束检查，防止后台页面及其依赖再次引入旧 UI、Sonner 或旧表单体系。

交付：全路由验收报告、构建和加载对比、依赖清理结果、发布记录与回滚信息。完整通过下节验收后上线最终版本。

## 验收标准

### 功能与业务

- 21 条受业务区权限保护的路由、后台登录和历史重定向入口逐一覆盖；包括各页面的抽屉、弹窗、空态、错误态和无权限态。
- 登录、会话过期、角色权限、深链和浏览器前进后退正确；按钮权限与 API 权限契约一致。
- 应用接入和上架、售卖配置、订单、授权、部署台账、托管运维与售后均能按现有规则操作；接口请求含义和业务 ID 保持一致。
- Retail、Edu 均作为应用样本；只读生产复查与隔离环境写入验收分别记录。
- 表单保存失败保留输入；重复提交受控；有变更时离开或切换能得到明确提示；危险操作确认内容准确。
- 门户购买、账户中心、自部署和托管部署，以及文档站完成回归，重点检查共享逻辑、样式和懒加载边界。

### 视觉与可访问性

- 检查 1440、1280、1024 和 390px 视口下的代表页面；检查明暗主题及系统主题跟随。
- 标题、边距、Tabs、筛选、按钮、表单、表格和抽屉遵循共享模板，无重复主标题和无意义的多层卡片。
- 桌面和小屏均可完成主操作；页面本身无意外横向溢出，表格滚动区域明确，活动标签可见。
- 检查键盘导航、焦点管理、弹窗关闭和焦点返回；图标按钮具备名称，字段错误可定位，状态不只依赖颜色。

### 工程与维护

- 完成 `npm run check`、`npm run test:admin`、`npm run test:integration`、`npm run test:e2e`、Storybook 构建及适用的依赖审计；所需数据库和服务按既有测试流程启动。
- 现有行为测试按 Ant Design 的实际交互更新，保留原有业务断言；新增测试集中覆盖状态所有权、字段错误、未保存变更、权限和危险操作等易回归场景。
- 后台及其视觉依赖无旧 `components/ui`、Radix、React Hook Form、TanStack Table 或 Sonner 使用路径；对动态导入和共享组件做传递依赖检查，不以直接 import 数量代替验收。
- 遗留依赖若服务于门户或文档站，应在清单中注明调用方；后台专用适配器清零。
- 比较迁移前后入口资源、后台懒加载资源及实测加载表现。门户可达的运行时模块图不包含仅供后台使用的 Ant Design，检查公共入口和 CSS 不意外加载后台资源。实测预算在阶段零建立，超出时先定位再决定优化。
- 后台基础控件直接使用 Ant Design；新增页面使用统一模板。共享封装有明确职责，避免形成第二套基础组件库。

## 提交发布与回滚

每阶段完成后提交、推送并记录覆盖页面、检查结果与未完成项。阶段代码先在迁移分支与预览环境验证；若新增分支名称，须同步当前 CI 的分支触发规则，或使用 PR 确保检查实际运行。

当前生产发布由 main 的成功 CI 或 main 上的手动工作流触发。合并 main 会进入生产发布链路，不能把 main 当作未验收阶段的暂存分支。

组件层和同一业务区内部必须完整迁移后才能形成生产发布批次。阶段一之后，可对已完整验收的业务区分批上线，每批同时回归尚未迁移的页面、门户与文档站。最终阶段执行全量验收，不长期保留两套后台入口或旧版切换。

沿用现有镜像构建、健康检查和部署机制，记录每次发布的 Git SHA 与镜像 digest。迁移以 UI 层为主，默认不需要数据库迁移；出现登录、权限、提交语义或关键交付操作回归时，将控制端恢复至上一份已验证镜像。新配置格式等超出 UI 的变更需独立处理，保证回滚不依赖数据降级。

当前两台腾讯云服务器仍承担既有控制端、备份和托管任务。后台升级部署到 Stack 控制端，Retail 和 Edu 的客户应用实例无需因 UI 换库重新部署。

## 完成判定

全部后台路由及嵌套界面使用 Ant Design，页面结构与 Edu 的共用模式对齐，业务行为验收通过，后台旧 UI 依赖路径清零，并完成生产只读复查，才判定整体迁移完成。进度按业务区和验收证据记录，不能用安装依赖、代码行数或修改文件数量推算完成百分比。
