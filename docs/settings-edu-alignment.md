# 文件存储与邮件设置对齐 Edu

以 `lingcoo-edu-oms/apps/admin/src/features/settings/SettingsPage.tsx` 的 `SETTING_FIELD_ORDER` 和服务端 Storage / Mail 设置定义为参照。对齐的是配置页面及选项的实际运行能力，不代表已迁移 Edu 的整个 Mail 业务模块。

## 文件存储

主配置固定八项，桌面按从左到右、从上到下排列，手机保持同一顺序：

1. 存储驱动：本地磁盘 / S3 兼容存储。
2. 存储访问密钥标识（AK）。
3. 存储访问密钥（SK）。
4. 存储空间名称。
5. 默认上传目录。
6. 存储区域。
7. 存储服务地址。
8. 强制路径寻址。

采用 Edu 的字段名称、说明、来源和敏感标记、密码显隐、圆角输入框及开关交互。默认上传目录仍使用 Stack 自己的 `stack/assets`。原 CDN 字段进入折叠的兼容设置，保存其他字段不会清空原值。

新增本地磁盘驱动使用 `STORAGE_LOCAL_ROOT`，生产默认 `/app/private-assets`，API 与 Worker 共享 `storage_assets` 持久化卷；不通过静态目录暴露文件，继续执行原素材权限与引用保护。本地连接测试验证读写并删除专属探针。目录不允许对象键越界或符号链接；根目录仅能由部署环境设置。运营者选择本地驱动时须将卷纳入文件备份，数据库备份不能替代文件备份。

迁移为历史对象补充 `provider=s3`，历史加密配置未写 provider 时也按 S3 解释。只要还有未清理对象，就禁止直接切换驱动或存储位置，避免文件失联。生产继续使用原七牛 S3，不因这次新增选项而切换驱动。

S3 支持成对 AK/SK；两者都留空且没有历史凭据时，使用 AWS SDK 默认凭据链以支持实例角色。只填一项会在连接测试与实际使用时被拒绝。七牛仍须配置账号 AK/SK。S3 服务地址继续要求 HTTPS。

## 邮件服务

主配置固定八项，顺序与 Edu 相同：

1. 投递方式：测试捕获（不外发） / 邮件服务器投递。
2. 邮件服务器地址。
3. 邮件服务器端口。
4. 直接加密连接。
5. 邮件服务器用户名。
6. 邮件服务器密码。
7. 发件地址。
8. 发件名称。

已配置的旧 SMTP 保持 SMTP 模式，补充默认显示名称 Stack；不会切换成 Capture。未配置页面采用 Capture、587 和非直接加密连接的默认展示。旧 `SMTP_FROM` 继续兼容，新增 `SMTP_FROM_ADDRESS`、`SMTP_FROM_NAME`、`SMTP_SECURE` 和 `MAIL_TRANSPORT`。

“测试 SMTP 连接”只连接和认证，不发送、不保存草稿。“发送测试邮件”独立放在折叠区域；Capture 返回 `simulated=true/sent=false`，实际业务 Worker 同样记录 capture 渠道与模拟标记。SMTP 发件头使用独立显示名称。密码不回显，空值保留原密码。

两页均显示配置数量，并提供与 Edu 一样的密文轮换确认交互：只使用部署的活动密钥重新加密数据库中旧密钥保存的敏感设置，不返回或修改明文。操作有权限控制和审计。

## 保留的 Stack 行为

后台数据库配置优先、环境变量兜底的现有优先级保持不变，避免本次界面升级切换线上已生效的连接；来源标记反映 Stack 实际生效来源。设置保存继续使用原有修订号和审计机制。未在此次修改中引入 Edu 的独立邮件模板、投递业务记录和加密正文模型。

## 验证

- 浏览器测试逐项断言两页八个标签的实际 DOM 顺序、完整下拉选项、密码显隐、连接测试独立请求、数字类型和失败草稿保留。
- SMTP 协议测试确认连接验证不发送 DATA、Capture 不连接网络、显示名称进入 From 头。
- 集成测试覆盖设置加密/密码保留、Capture 的 API 与 Worker 结果、连接草稿不落库、密文轮换授权与重复调用。
- 本地存储测试验证跨 Provider 实例读写、越界和符号链接拒绝、幂等删除、实际素材读写与驱动切换保护。
- 最终生产验收使用只读页面检查，不向未经确认的收件人发送邮件，不切换生产存储驱动。
