# 托管实例受控镜像升级

## 本批适用范围

只替换现有应用的 `APP_IMAGE`。Compose、服务清单、挂载、数据库版本和 schema 必须不变；不执行初始化、迁移或任意命令。新版启动过程也不得自动迁移 schema。是否符合条件必须由应用维护者通过旧/新版本兼容性验收确认，平台不会仅凭版本号推断兼容。

如果版本含数据库迁移、破坏性格式变化、外部状态迁移或部署结构变化，本流程不适用。跨节点灾难恢复与客户数据恢复另设流程，不能直接套用此按钮。

## 版本登记

运维先验证交付镜像、健康检查、业务读写兼容及回退，再在目标节点预加载旧/新固定摘要镜像。不能只预加载可变 tag。接着在节点私有 `node.json` 的 `upgradeReleases` 数组登记：

```json
{
  "id": "00000000-0000-4000-8000-000000000001",
  "appCode": "application_code",
  "label": "经兼容性验证的发行版本",
  "fromImage": "registry.example.com/app@sha256:<旧版64位摘要>",
  "toImage": "registry.example.com/app@sha256:<新版64位摘要>",
  "schemaPolicy": "no-migration",
  "reviewEvidence": "对应源码提交、CI/兼容性验收记录，以及启动不执行数据库迁移的审核结论"
}
```

示例不可直接用于生产：需使用真实唯一 UUID 和摘要。每个 UUID 对应不可变计划，变更计划使用新 UUID；复用 UUID 的不同计划会被拒绝。登记属于受信任运维操作，不允许客户提交镜像或命令。审核说明不得包含密钥。节点只有通过适配包摘要和镜像存在性检查才上报目标。

本批没有为现有 Retail/Edu 凭空登记新版本：缺少正式兼容性证据时后台会显示暂无可升级版本。发布应用新版后应先完成上述验证。

## 后台使用

在“托管运维 → 托管实例 → 受控升级”查看当前镜像、可用版本和历史。选择目标，核对审核依据，输入完整实例编号确认停服维护。

平台将实例置为维护状态，保留所有资源预算，拒绝其他并发运维/退出动作。节点再次核验来源、白名单、固定镜像及数据归属，停服后制作完整冷快照并上传异机加密仓库，再启动新版并验证服务与 HTTP 健康。

成功后记录新镜像和备份证据；新版本不通过则恢复旧配置/镜像，保留当前数据并验证健康。发生未知中断时，同一任务再次执行会保守回退，不盲目重跑新版。回退也失败时继续保持维护状态、原任务及预算，每五分钟允许同一任务重试；维护超过一小时或节点失联进入监测。不得手动把状态改成就绪掩盖故障。

回退是同 schema 的代码回退，不覆盖数据卷；升级时及新版本运行期间产生的数据不会被旧快照自动覆盖。升级前冷备份按既有备份策略保留。

## 验证边界

集成测试覆盖权限、源版本/目标白名单、并发与幂等、维护互斥、节点绑定、备份证据及不可变审计。独立 Docker 样例验证真实升级、失败回退、中断恢复、回执重放和持久文件保存。生产既有实例只做只读状态与入口验证，不把测试样例算作 Retail/Edu 新版本兼容性认证。
