# Stack 应用部署业务与自管托管方案

更新：2026-10-07。当前为业务工作流实施阶段；尚未接入真实托管执行器、DNS 或 TLS，不能作为托管上线验收。

## 当前决策

只提供客户自有服务器（`self_hosted`）和 Lingcoo 自管虚拟机托管（`managed`）两种选项。停止 CloudBase、SAE、多云资源拼装及 BYOC 方案。应用由团队维护，以版本化镜像交付；不建设第三方开发者平台、分账或应用内账号体系。原方案留在 [历史档案](archive/app-lifecycle-multicloud-proposal-2026-10-03.md)，不再执行。

## 客户业务流程

1. 浏览应用、购买、支付确认、获得权益；部署仍受权益有效期及实例配额约束。
2. 选择已购买的应用及部署方式，填写应用 Manifest 声明的必填配置。应用初始化凭据遵循现有加密存储规则。
3. 自有服务器：填写合法 IPv4/IPv6、应用域名及必要配置，创建部署记录后领取短期 deploy token，在自己的服务器运行安装命令。填写 IP 不代表平台获得 SSH 权限，也不会自动远程安装。有服务器并不意味着已有域名；客户需自行准备域名及解析。
4. 平台托管：填写子域名前缀或留空自动生成，平台预留 `xxx.app.lingcoo.com`。服务器 IP、安装路径、域名槽位及资源规格由平台确定，客户端不能指定。
5. 无可用节点时显示“等待可用容量”；分配成功显示“等待部署接入”。两者均不是部署成功，不发安装令牌，不展示可访问链接，不写入成功部署时间。
6. 申请阶段允许取消并释放节点预留容量。域名前缀保留，不立即转给其他客户；域名回收另行设计。取消后其他申请可在下一次节点报告或主动重试时获得容量。

## 节点选择和隔离边界

后台“托管服务器”登记节点，设置可分配 CPU、内存和磁盘预算，默认停用。预算需扣除系统、代理、备份及现有服务开销，不能直接按机器标称规格填满。

节点运行 `scripts/hosting-node-report.py`，每分钟报告 Docker/Compose 状态、CPU 余量、可用内存和数据盘空间。只选择已启用、最近五分钟内报告且资源满足要求的节点。分配同时受配置预算、实际报告余量和已预留容量限制；事务锁防止并发超额分配，按剩余比例选择节点，等待队列按创建时间处理。探针是容量估算，不能代替压力测试和运行时配额。

每个实例规划独立 Compose 项目、网络、卷、数据库及凭据；共享宿主机，不共享客户数据表。当前代码只做容量预留，尚未创建这些运行资源。

应用 `meta.hostingProfile` 由平台配置，包含 `enabled`、Manifest 单域名字段 `domainField` 和 `resources`（`cpuMillis`、`memoryMb`、`diskMb`）。未配置或不兼容的应用只能自部署。Retail 初始申请规格为 2 核 / 4 GiB / 20 GiB，属于保守初值，尚未证明某台机器可承载多少客户。

## 本阶段接入步骤

1. 发布代码前执行数据库迁移 `0029_managed_hosting_workflow`；旧部署默认归为自有服务器。配置 `HOSTING_DOMAIN_SUFFIX=app.lingcoo.com`。
2. 通过既有应用导入流程同步 Retail 商品元数据；商品仍为验收状态，不自动开放售卖。检查 hostingProfile 和 Manifest。
3. 管理员在 `/admin/hosting` 登记节点，保存仅返回一次的报告令牌。若丢失，当前需管理员重新规划节点凭据，不应重复使用未知密钥；令牌轮换后续补齐。
4. 在节点创建权限 600 的私密 JSON 文件（不要提交仓库）：

```json
{
  "stackUrl": "https://stack.lingcoo.com",
  "nodeId": "节点 UUID",
  "reportToken": "后台返回的令牌",
  "dataPath": "/opt/lingcoo"
}
```

5. 安装 Python 3、Docker 与 Compose，准备数据目录，运行 `python3 scripts/hosting-node-report.py /私密路径/node.json`；设置每分钟执行一次。检查后台报告后启用分配。
6. 使用测试权益分别走两种分支，验证前缀冲突、无容量等待、分配、取消释放及越权拒绝。本阶段不需要变更 DNS，不会远程启动应用。

## 下一阶段顺序

1. 接入节点任务执行器：领取任务、校验镜像版本、创建隔离目录/网络/卷、注入加密配置、迁移数据库、启动应用；具备幂等、失败清理与重试。
2. 实际运行资源设置 CPU/内存限制，并区分“待启动预留”和“已运行占用”，避免重复扣减实时资源报告。
3. 接入节点反向代理与域名映射。`app.lingcoo.com` 本身可作为说明页；真正承载实例的是 `*.app.lingcoo.com` 及具体主机记录。多节点需按实例指向所属节点，或统一入口转发；不能把泛解析同时指向多台独立节点并期待自动找到实例。
4. DNS、TLS 和外网健康检查全部成功后，才切换 ready 并返回 HTTPS 访问地址。自定义域名需验证归属后再绑定。
5. 做异机备份和恢复演练、磁盘/容量告警、版本升级回滚、故障节点迁移及真实容量压测，再开放正式托管服务。

托管费用商品、续费、欠费处理尚未实现，不自动计费，也不表示购买应用即获得无限免费托管。业务账号及部署后应用如何使用不属于 Stack 的管理范围。
