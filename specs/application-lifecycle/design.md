# 设计

## 边界

应用模块拥有服务连接、应用来源、构建和交付版本。GitHub 持有源码和运行 CI；ACR 持有镜像；Stack 不在 API 进程编译代码。部署模块通过应用模块公开端口读取发布快照。应用内部账号与业务不属于 Stack。

第一供应商 GitHub，公开读取无需令牌；私有读取通过加密服务连接。用户 URL 只允许规范 github.com 仓库，服务端只访问固定 api.github.com。提交解析后所有文件固定同一提交。配置解析有大小限制、禁止 YAML 别名膨胀和重复键。文件上传与 API 使用相同校验器。

## 接入文件

默认 `stack/app.yaml`，同时支持 `stack/app.json`。一份应用定义包含 schemaVersion、app、features、source build、images 和 delivery。Compose 可嵌入或引用仓库内文件，导入后保存解析快照。软件定价、连接凭证和实例密钥由 Stack 管理。免部署 kind=none；容器部署 kind=compose。

新协议与现有 Manifest v1 并存；旧执行路径继续可用。新协议不会伪装成现有专属 Adapter 已能运行，统一执行能力接通前应明确阻止不支持的交付。

## 状态与安全

来源导入创建 inactive 草稿。定义更新保存候选快照，不自动覆盖商品和运行实例。版本以应用+版本号唯一，绑定提交、所有镜像摘要和定义摘要。发布不等于商品激活；撤回禁止新部署，历史快照保留。CI 使用应用专属、可撤销、只登记草稿的发布凭证；不得使用管理员会话或应用业务 AppSecret。

连接密钥 AES-GCM 加密，读取仅返回 configured。导入/更新/版本登记在事务和应用级锁内执行并记录事件。并发与失败不得留下半个应用。发布镜像由平台按登记仓库进行可访问性校验；运行实例引用阻止误删。

## UI

沿用已确认 Ant Design 设计系统，主色 #2563eb，背景 #f5f6fa，文字 #1f2937，现有字体 token。已有设计系统优先于技能默认字体及非对称布局建议。应用列表增加从仓库/文件导入；应用内源码与构建、交付版本使用表格和抽屉，不添加独立重复菜单。预览确认、缺项提示、返回路径、错误恢复必须可操作。

## 验证

契约单测：错误引用、秘密默认值、无摘要、危险 Compose、身份变化。集成：事务、权限、幂等、私有凭证隔离、发布门禁。浏览器：文件与仓库导入预览、重复冲突、版本操作和返回。部署：通用 Compose 样本、Retail/Edu 迁移、自部署和托管、备份恢复与版本更新。

## 开发交付模板（已实现）

`app:create` 从 Stack 同一套契约和语义校验器构建独立 Node 工具，生成到新目录。应用仓库直接保存该工具与 SHA-256，CI 在构建前验证定义、登记前验证全部镜像摘要。服务端再次验证，不信任客户端输出的通过标志。生成器不覆盖现有仓库，不自动写入真实密钥或申请云资源。

Compose 模板的单服务样本先运行源码测试与实际镜像启动检查，再给同一个本地镜像打仓库标签并推送，避免测试产物和发布产物不一致。免部署模板不构建容器，要求维护者接入自身应用构建与授权检查。两套工作流都仅登记草稿。

## 通用执行与数据交接（分阶段实现，客户入口尚未启用）

当前已支持 generatedSecrets 与 lifecycle.infrastructure；内部 ComposeBindingService 固定版本/计划并加密存储实例配置，compose-install.py 消费私密任务、执行安装与记录步骤。实例绑定受数据库不可变触发器和外键保护；配置密文纳入平台密钥轮换。准备服务只接受同应用已发布版本，目前没有接入公开部署 API，因此现有发布门禁未被绕过。

本阶段节点仅提供内部执行内核，不承担鉴权、调度、域名、备份恢复或发布授权；这些外层流程仍需后续接通。以下约束覆盖完整目标，未实现的部分不得作为已支持字段使用。

1. **实例绑定**：创建实例时固定 releaseId、releaseDigest、计划和协议版本。任务重试读取同一快照，不重新读取 main、不使用镜像 tag。已有实例更新必须是独立升级任务。
2. **配置生成**：平台声明支持的随机密钥生成方式，每个实例首次创建时生成并加密持久化；重试复用原值。应用通过服务环境变量消费密钥，在容器内组合连接信息；生成配置不允许执行仓库代码。只返回客户确实需要的初始化凭据。
3. **启动顺序**：显式声明初始化前需要的基础服务，等待其健康后，使用一次性应用容器执行迁移、初始化命令，再启动全部长期服务。命令采用 argv，只在声明的容器内执行。应用保证重试安全；执行器保存步骤结果与失败阶段。
4. **备份交接**：每份备份有稳定键、大小上限和配对恢复命令。备份命令通过 stdout 输出二进制数据，恢复命令从 stdin 读取；诊断信息走 stderr，平台不将数据或原始密钥输出到日志。平台负责校验和、加密、异机保存、保留策略；应用负责内容完整性。
5. **一致性**：应用声明备份前需要暂停的写入服务以及恢复顺序，执行器记录原运行状态并在成功或失败后按规则恢复。数据库容器或应用内备份工具承担数据库一致性，不以复制活动数据库目录替代可恢复备份。
6. **恢复验收**：默认在新建、隔离的验收实例恢复并核对业务测试数据。覆盖现有实例的数据恢复走明确的运维任务，包含预备份、停写和审计，不能混入普通部署重试。
7. **两种部署复用**：客户自部署和平台托管复用计划和执行内核。外层分别负责 deploy token 交换或节点任务领取，以及客户 DNS 检查或托管资源分配。网关与 DNS/TLS 验证是运行就绪之后的履约步骤。
8. **验收证据**：平台保存与 releaseDigest、执行器版本、运行架构绑定的结构、拉取、初始化、健康、入口、持久化与恢复结果。发布门禁由服务端根据实际证据判断，不允许通过导入文件中的布尔值跳过。

Retail 样本目前还在专属适配器中完成配置生成、基础服务启动和初始化；通用协议必须覆盖这些实际需求后才能替换。切换通过新测试实例验证，保留旧实例原执行路径和既有数据。

### 通用托管协议交接

`deployment_compose_bindings` 固定服务器与回环端口；端口通过服务器级事务锁分配，并由数据库 `(server_host, loopback_port)` 唯一索引兜底。未清理的停止实例继续占用端口，绑定后禁止通过普通编辑换服务器、模式、应用或运行配置。新通用实例使用 24000–29999 的平台预留范围，执行器另行检查实际 socket，冲突时拒绝执行而不是停止其他进程。

节点只有在本地平台内核与 `composeRunnerSha256` 一致时才声明 `compose_install_v1`。托管任务携带固定安装计划，节点消费声明，不导入应用仓库 Python；镜像凭证使用临时 Docker 配置目录。安装成功后生成无密钥的路由记录，通过绑定指纹验证入口容器和隔离网络，网关继续复用现有 DNS、通配符证书及自定义域名 HTTPS 履约。

服务端完成任务时校验实例、版本、摘要和完整初始化步骤，并保存节点运行证据。运行就绪与公网就绪分别判断；这份已发布版本的安装证据不能用于绕过尚未完成的草稿版本发布验收门禁。

后续接入需要固定客户创建时选择的版本和声明，不能读取随应用编辑变化的配置；等待资源的实例应先保存期望版本，分配节点后再固定端口。客户自部署入口必须兑换已有 deploy token、校验平台执行器摘要并复用同一安装绑定。Retail 的初始化容器环境、入口配置文件和数据库/文件备份产物需先标准化，再做真实应用验收；不能用测试镜像的就绪结果替代这些验收。
