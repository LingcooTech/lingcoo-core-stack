# 实施设计

首先构建 deployment 模块拥有的只读管理员查询，不将部署并入 installs。契约包声明分页白名单响应，专用 deployments.view 权限开放给客服、运营、管理员。现有客户权限与运维写权限保持独立。

界面沿用已验收工具型后台：主色 #2563eb，成功 #15803d，警告 #b45309，异常 #dc2626，底色 #f8fafc；实际使用现有语义 token。沿用 PingFang SC/Segoe UI 字体作为既有设计系统例外。24px 页面留白，顶部说明和筛选，横向可滚动表格与右侧详情抽屉。桌面与手机浏览器均验证。

台账查询在数据库筛选、计数和分页。只返回明确定义的身份、状态、关联及域名字段；不复用包含交付敏感信息的内部实体。部署状态与最近报告分别表达，创建记录不表示部署成功。售后链接尊重工单权限，托管入口尊重 settings.manage 权限。

后续阶段复用现有 jobs、通知、审计和节点协调器；以小步可部署变更推进，商业策略未配置时保持明确“未配置”状态而不推断无限服务。禁止在验证期间对现有业务实例执行破坏性恢复或回收。

## 计费决策（用户 2026-10-08 补充）

应用与托管分别计费，允许合并订单、一次付款；必须保留独立明细和履约对象。采用月付与年付，先支持主动续费，不实施代扣。正式价格未指定，不自行上架销售。

按自然月/年计算，使用原始周期锚点处理月底、短月和闰年，避免固定 30/365 天和日期溢出。参考：https://docs.stripe.com/billing/subscriptions/billing-cycle 。首次托管服务期从就绪交付开始；付款产生待激活服务资格，不能让部署排队或失败消耗服务期。续费与退款必须关联托管服务，不增加软件部署权益数量。

现有订单为单套餐模型，因此组合购买必须增补订单明细、独立托管履约及退款关联，不能仅修改订单总价或复用软件有效期。原有单品订单需兼容。告警接收渠道仍未指定。
