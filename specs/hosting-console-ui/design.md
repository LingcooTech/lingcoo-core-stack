# 托管控制台与客户端安装信息架构

目的：管理员先判断资源与实例是否正常，再进入具体节点或任务处理；消除客户端安装登记与服务器部署记录的混淆。

风格：工业工具型控制台。沿用 Stack 的现有设计系统，保留 --font-sans（PingFang SC、Segoe UI 等平台字体）作为品牌一致性例外。主操作蓝 #2563eb、正常绿 #15803d、警告橙 #b45309、危险红 #dc2626、底色 #f8fafc，实际使用已有语义色令牌并支持深色模式。

布局：页面统一 24px 留白，顶部统计与状态概览，主体标签页为服务器资源、托管实例、运维记录。节点采用紧凑双栏卡片；详细清单放右侧抽屉，编辑与登记用对话框，低频技术字段折叠。移动端单列；长表格在容器内滚动。

数据边界：installs 是客户端登记与用户绑定，不是 deployments。菜单及客户关联文字改为“客户端安装”，保留现有路径、权限和 API；托管入口改为“托管运维”，不把客户端活跃状态当作服务器健康。自有服务器由客户运维，本页托管操作只针对平台托管实例。

实现范围：仅管理前端、导航元数据和说明；复用既有 API、权限、任务及数据结构。确认操作、错误提示和一次性凭据保留。沿用已获授权的自动验证、提交与生产发布流程。

## 管理入口与使用方式

| 入口                         | 管理对象                     | 常用操作                                                         |
| ---------------------------- | ---------------------------- | ---------------------------------------------------------------- |
| 客户管理 → 客户端安装        | 通过安装接入协议登记的客户端 | 查安装标识、应用版本、用户绑定、最近上报，关联工单与授权         |
| 运维 → 托管运维 → 服务器资源 | 平台登记的服务器             | 看总量、实际占用、托管预算、证书状态；查看容器清单、编辑资产信息 |
| 运维 → 托管运维 → 托管实例   | 平台托管的应用部署           | 查访问入口、服务状态和备份，确认后提交重启或备份任务             |
| 运维 → 托管运维 → 运维记录   | 节点执行的运维任务           | 追踪等待、执行、成功和失败结果                                   |

客户端安装不等于服务器部署。原有 `/admin/installs` 地址及 `installs.view` 权限不变；拥有 `settings.manage` 权限时，页面提供前往托管实例的入口。托管页通过 `?tab=servers|instances|operations` 支持直接打开对应标签；旧称“安装实例”仍可用于命令菜单搜索。

数据保护说明：页面显示的本机备份和异机副本来自节点上报；报告过期、备份失败或超过 36 小时时单独提示。重启只提交已有运维接口的任务，确认窗口说明数据库继续运行。添加服务器后的上报凭据仅显示一次，必须确认保存后才能关闭。

验证覆盖：浏览器自动化检查操作确认与防重复、节点编辑日期及监控节点分配限制；实际数据的只读浏览器验收覆盖资源抽屉、容器搜索、编辑窗口、取消操作、任务记录、客户端说明、标签深链接和移动布局。不会为界面验收重启生产托管实例。
