# Stack 底座收敛实施记录

基线：Stack `82d6f69`，参考 Starter `a192f80`。本轮按认证、模块职责、协议与回归三个阶段实施，使用独立分支 `codex/stack-foundation-convergence`。验收依据实际行为与自动化检查，不以目录数量或测试数量代表稳固性。

## 1. 认证正确性与会话生命周期

目标：浏览器使用 HttpOnly 会话与绑定会话的 CSRF 校验；原有 Bearer API 保持可用，改密、重置、停用后旧凭据失效；验证码消费、凭据修改和事件共享事务。验证并发消费、故障回滚、登录退出、会话撤销、主体权限与浏览器刷新。

已实施并验证：31 个单元测试、43 个真实 PostgreSQL/HTTP 回归、4 个浏览器流程通过；两端类型、构建与模块门禁通过。浏览器首次认证清理缓存曾中断公共配置加载，已修正为保留公共站点配置缓存，首次加载和深链接浏览器验收通过。数据库迁移 0027 空库、重复运行与旧库升级通过。生产发布尚未执行。

## 2. 模块职责与最小依赖

目标：模块自行声明所需能力，Composition Root 负责组装，模块不能依赖全局工厂；继续拆分集中的配置和应用用例；设置持久化归属 Settings；加强门禁与负例测试，保持跨模块事务。

已实施并验证：模块通过自身依赖接口只取得使用到的公开方法；模块门禁拒绝 Composition 导入与旧设置桥接导入。设置持久化迁入 Settings，部署设置迁入 Deployment；密钥轮换在组合根统一编排事务。Manifest 同步拆为独立用例，并验证事件失败时回滚、远程获取期间的元数据并发更新不丢失；部署 bootstrap 组装拆为纯函数，生成命令参数统一转义。事务内查询批处理改为顺序执行，池化读取保持并发，避免 pg 客户端并发查询的弃用行为。33 个单元测试、46 个 PostgreSQL/HTTP 回归、4 个浏览器流程、两端类型和构建均通过。第一阶段远端 CI 和 Docker Verify 成功。

## 3. 业务协议与回归

目标：补齐业务响应契约与客户端校验，检查路由契约覆盖；启用严格类型选项与统一格式检查，收敛 lint；为此前缺少验证的内容、文档、工单、AI、存储和通知补充适当的权限、隔离、异常及协议回归。执行完整工程、数据库、浏览器与生产镜像验收。

已实施：业务响应模型迁入共享 Contracts，Admin 导入其推导类型；SDK 对未知或不合法成功响应抛出协议错误，返回 Schema 解析结果，并支持显式 Schema 的类型推导。所有 `/v1` JSON 路由在注册阶段检查响应契约，付款通知的两个文本协议单独列举；增加后端覆盖、客户端方法/路径匹配与协议负例门禁。兼容的泛型客户端调用仍保留，不能将其描述为所有调用均由 Schema 自动推导。

两端及共享包增加严格索引访问、覆盖与 switch 检查；必要的写入和投影检查空结果，同时保留条件更新、去重和抢占的空结果语义。两端 lint 门禁为零警告，统一格式检查成为 `npm run check` 的必要步骤；本阶段包含此前格式基线的机械规范化。架构说明更新为当前模块归属、最小依赖、事务和扩展约束。

补齐内容发布、文档、工单、通知、AI 与七牛签名的真实数据库/HTTP 回归；修复内部文档公共泄露、Admin 用户更新方法不匹配、微信设置路径缺失版本校验等问题。内部和隐藏文档仍可由管理员管理。外部内容与 OpenRouter JSON 使用 Zod 解析；AI 使用短事务预留额度，并发争用最后一个名额时只调用一次 Provider，失败结算释放预留。认证组件增加 Chromium 测试，覆盖初始化竞态、会话失效、角色刷新与退出失败。

开发工具链 esbuild 的受影响传递依赖限定升级到 `0.28.2`，保留 Drizzle Kit 与 Vite/Storybook 原有直接依赖版本。全依赖审计为 0 项漏洞，Drizzle Schema 导出通过；CI 将全依赖门禁提高到中危。漏洞依据：[旧版开发服务器 CORS](https://github.com/advisories/GHSA-67mh-4wv8-2f99)、[Windows 开发服务器路径问题](https://github.com/advisories/GHSA-g7r4-m6w7-qqqr)。

## 4. 持续治理增强（基线 f10c873）

本轮分为三个阶段：依赖与工具链治理；迁移生成与架构门禁；端点契约与模块内部职责。每阶段独立验证、提交并推送，延续当前分支。

第一阶段：修复 lint-staged → micromatch → braces 开发依赖漏洞链；统一 Node 22.23.2、npm 10.9.8 与 Node 22 类型声明；安装、开发、检查和提交时验证工具链；提交钩子以参数数组执行文件处理；定时和提交审计统一按中危阻断。此前“0 漏洞”为当时快照，后续以每次实时审计为准。

第一阶段本地验收：统一工具链下 `npm run check` 全部通过，包含 38 个单元测试、两端类型和生产构建；全依赖审计为 0 项漏洞，错误 Node/npm 版本被明确拒绝。基础镜像的定期更新纳入 Dependabot，版本漂移会由构建期检查阻断。

第二阶段：新增 0028 向前迁移及生成快照，校准历史约束名称、事件 app 外键、部署权益索引及枚举顺序；安装记录的非空 app 外键明确采用 RESTRICT。迁移遇到历史孤立事件会停止并回滚，要求人工核对业务数据后重试，不自动删除或改写数据。`check:schema` 验证最新快照与声明一致且不产生增量 SQL；真实 PostgreSQL 对照历史迁移和 schema 新建库的列、约束、索引、枚举。

边界检查新增局部表别名、未知写入目标、辅助文件私有导入、原始数据库执行及拆分 schema 的归属校验。模块装配索引、Composition 与 CLI 脚本为组装入口，业务模块不能导入这些入口。部署行锁归属 Deployment，权益行锁通过 License 端口提供；事务 advisory 锁仅开放参数化的固定基础设施函数。两端与共享包启用类型感知的异步 lint；浏览器事件适配器同步传递事件、统一处理未捕获拒绝。单元测试 40 项、数据库/HTTP 56 项、浏览器组件 6 项、E2E 4 项通过。第一阶段远端 CI 与 Docker Verify 均通过。

## 发布限制

浏览器从旧 localStorage Token 切换到服务端会话后需要重新登录。发布须先迁移数据库再启动新版 API，旧版 JWT 在账户凭据版本为 0 时仍可用，版本提升后失效。生产密文轮换、真实外部 Provider 验收和异机灾备属于单独的运行操作，本轮不会把模拟验证表述为真实外部系统验证。

旧版 API 不检查账户凭据版本，回退到该版本会丢失本轮的 Bearer 撤销保障；恢复时应使用支持会话/凭据版本的已验证镜像，或另行制定签名密钥切换方案。

AI 预留在进程崩溃或结算失败时保守计入当前滚动窗口，最长占用 24 小时。Token 预留沿用输出 `maxTokens`，不包含完整输入成本，因此不能承诺精确计费硬上限。本轮验证使用本地 Provider 协议替身，没有执行真实供应商扣费或生产密钥操作。生产规模负载与异机恢复仍需独立演练。当前 Schema 集中定义和较大的部署配置服务可继续拆分；本轮门禁证明已覆盖的行为，不能证明未来所有业务都不会出现底层问题。
