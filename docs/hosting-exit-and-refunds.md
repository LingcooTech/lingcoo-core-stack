# 托管退出与退款

## 操作流程

1. 客户在部署详情的“服务退出与数据交接”填写退出原因；运维也可代登记。申请后阻止续费和重启，业务暂时仍运行。
2. 运维在托管实例中填写保留天数（不得短于购买政策），确认停服。节点需要在线、已安装退出执行器、已配置加密异机备份与固定摘要快照镜像。
3. 节点校验 UUID、项目、服务与卷归属，禁止自动重启，停止全部实例容器。随后制作所有声明数据卷的冷快照、部署配置与 SHA256 清单，保存异机加密副本。
4. 节点回报有效证据后，界面显示“数据保留中”。CPU/内存预算释放，磁盘预算继续保留。失败、节点离线或回执丢失保持原任务与预算，节点继续核对同一任务。
5. 运维通过受控渠道交付数据，在平台登记不含密码的交接说明/工单编号；客户登录后确认已收到并核对数据。
6. 服务结束后，财务可在原分项退款账本审核退款。平台不自动认定退款比例，不自动发起退款。原支付、续费、服务期及退出事件保留可追踪记录。

自有服务器仍由客户自己运维。本流程只管理平台托管实例；不远程停止客户自有服务器。

## 权限与并发

客户只能读取、申请和确认自己的退出记录；运维执行停服和登记交接；财务按原退款权限处理。请求编号、版本、单实例运维互斥和部署事务锁防止重复操作。退出期间旧续费订单到账进入人工处理，不继续增加服务期。未完成交接的全退仍被拒绝；失败退款不将绑定资格恢复为可部署状态。

## 数据与恢复限制

冷快照为 `lingcoo-cold-volumes-v1`，包含 `manifest.json`、`SHA256SUMS`、各卷 tar 和私有配置。目录权限 0700，配置和卷归档为 0600；异机副本由既有 Restic 仓库加密。只能通过受控运维渠道访问，不在后台暴露仓库密钥或原始下载地址。

恢复需先核对全部 SHA256，使用记录的数据库与应用镜像版本，将卷解包到新建的隔离卷，完成应用健康及业务数据核验后再交接或切换。不可将物理数据库卷直接当作跨主版本迁移包。

当前已提供人工交接凭证与客户确认，尚未提供自动到期下载授权和独立密钥交付。到期不会自动删除卷、备份、DNS 或域名绑定；可审计回收另行实施。原子化整机/跨节点迁移切流仍是独立阶段。

## 节点更新

`upgrade-hosting-exit.py` 校验经过评审的四个运行脚本摘要，在节点全局锁内备份并替换，保留原配置；不会调用任何实例停服操作。只监控节点不上报退出能力。执行节点使用本机已有固定摘要 Caddy/Alpine 镜像中的 tar 工具制作冷快照，升级前实际验证工具存在。

## 验收标准

数据库回归验证租户/权限隔离、幂等、保留政策、迟到付款、退款保护和失败重试。真实 Docker 样例验证停服、失败异机上传不误报、原任务重投、关闭自动重启、卷快照和隔离恢复；CI 样例的远程仓库调用为替身，不当作真实异机传输验收。已有生产异机备份能力单独验收，现有 Retail/Edu 不执行停服测试。
