# 设计

清理按精确容器归属、挂载引用、网络引用逐项校验；删除专属资源，保留共享镜像和其他业务。先移除旧代理配置并验证 Nginx，再删除旧目录。

应用协议由运营者安装并校验摘要，任务不得选择可执行路径。核心保留授权、资源预算、目录/卷归属、任务日志、网络和网关控制；适配器声明服务、持久卷和生命周期。现有协议需显式迁移，未知应用拒绝执行。

微信支付遵循官方直连商户 V3 协议，复用项目支付提供者接口；使用原始报文验签、AES-256-GCM 通知解密，验证商户、订单、金额与签名密钥标识。管理配置、就绪检查与测试同步调整。

## 托管协议 v2

`hosting-adapter.json` 声明 `protocolVersion: 2`，以及服务权重、应用/基础服务、健康服务、持久卷、镜像变量、初始化命令、入口服务和端口、域名环境变量及需重建的服务、备份脚本。`stack-delivery.py` 提供 `hosting_configuration(values, port)` 和 `prepare_hosting(directory, port)`，应用负责处理自身 Compose 与配置。

适配器只能由运营者安装；核心校验文件摘要并拒绝未知协议、应用和归属不匹配的实例。取消隐式 Retail 回退，节点必须报告已校验适配能力才可被分配。已有旧实例的归属由迁移脚本核对实际 Compose 项目后一次性补齐。

异构验收采用 nginx 静态应用，没有 API、Worker、PostgreSQL 或 Node.js 初始化命令，验证实际 Docker 安装、重复执行、备份及隔离恢复。应用适配器仍以 Python 作为交付工具接口，运行中的应用不受语言限制。
