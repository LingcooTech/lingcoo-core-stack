# 受控镜像升级：需求、设计和验收

## 本批需求

- 当运维选择节点登记的审核版本时，平台仅接受固定源/目标摘要、同应用、无需迁移且结构不变的升级。不得让任务传入命令、路径或任意镜像。
- 当实例有退出、其他任务、未解决升级或节点不新鲜时，平台拒绝升级；提交后进入维护状态并保留全部预算。
- 节点执行前再次验证白名单、当前镜像、适配包校验和及旧/新镜像本地存在。停服前预检失败不改变服务；停服后须完整冷备份和异机证据。
- 当新版本健康检查通过时，记录当前镜像与证据；当升级失败或执行中断时，重试先回退旧镜像并验证健康。回退失败保持维护和同一任务，不虚报就绪，不恢复旧数据覆盖客户写入。
- 完成回执丢失时，节点重放同一证据；平台记录不可变目标和结果。现有 Retail/Edu 不作为升级破坏测试对象。

## 范围与协议

本批只支持 APP_IMAGE 替换；配置、Compose、数据库版本及 schema 不变，不运行初始化/迁移命令。审核发行登记放在节点私有 `upgradeReleases` 中（固定 UUID、appCode、label、fromImage、toImage、schemaPolicy=no-migration、reviewEvidence）。必须经过发行兼容性验收并预加载固定镜像；平台从节点报告列出可用目标。没有已验收的新 Retail/Edu 版本时不伪造可升级目标。

复用节点锁、托管任务队列、冷快照及异机备份。新增独立升级台账存冻结计划/结果；平台使用 maintenance 状态，操作失败保持保护并可安全重试。节点维护操作日志与原配置备份；中断恢复保守回退，不重复尝试未知副作用。数据库迁移型升级、任意恢复点回退、跨节点迁移/切流为后续独立流程。

## UI

目的：运维看清当前镜像、合格版本、停机与回退结果。Web 托管实例卡片增设折叠区，复用既有工业工具型后台、字体 token、蓝色主按钮、灰白背景和状态色（现有设计系统优先，不更换字体）。先展示资格/阻断原因，再选择版本及确认维护，下面显示时间和历史结果；沿用 Lucide 与现有控件。客户侧维护状态可见。
