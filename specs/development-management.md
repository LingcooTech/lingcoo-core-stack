# 开发管理与商品交付边界

开发管理独立于商品管理：开发连接 → 仓库浏览 → 开发项目 → 构建与不可变交付版本 → 创建商品草稿 → 选择交付版本并上架。开发项目可以在商品创建前存在、构建、登记版本；创建商品不自动上架。已有应用、版本、授权及实例的 ID 保持不变。

开发项目拥有仓库来源与最新候选定义；商品只消费已验证的发行快照。同步源码不会覆盖商品展示文案或运行实例。交付规则由应用声明，商品编辑只读展示；实际平台预设在独立交付设置中维护，客户参数在部署时填写。

GitHub 浏览只展示凭据可见的仓库；ACR 企业版资源列表需要管理 API 只读权限，与 Docker 拉取凭据分开。个人版不提供管理 OpenAPI，仓库目录来自开发项目声明，也可输入指定仓库查询标签。外部列表分页；GitHub/Registry 响应限长，管理 API 限定端点和超时，不回传密钥。连接删除前检查开发项目引用。

实施顺序：

1. 建立独立开发项目及存量关联迁移，兼容已有 CI 发布地址。
2. 建立开发管理入口、连接管理、GitHub 仓库与 ACR/Registry 镜像浏览。
3. 将源码、构建、版本移出商品编辑，商品交付定义只读，预设独立管理。
4. 验证项目先于商品、导入与同步边界、版本不可变、权限及现有部署兼容；完成提交和发布。

验收不以移动菜单代替数据分离，不以模拟外部响应代替真实账号权限验证。缺少外部凭据时明确显示配置要求。

## 验证与能力边界

- 存量升级验证保留了 131 个应用、11 条源码关联、9 个交付版本、2 条构建和 3 个 CI 凭证的 ID 与商品配置。
- 全新测试库完整集成回归 147 项通过；个人版 Registry 目录与游标分页专项在内的最新专项 15 项通过。
- 后台组件浏览器回归 34 个文件、81 项通过；独立开发项目和商品之间的导航、交付版本选择另由端到端测试覆盖。
- 端到端 16 项验收通过：完整回归 14 项通过，发布按钮中文空格与侧栏动画等待修正后，两项专项复验通过。生产构建、静态入口、迁移快照、模块边界、前后端 lint/typecheck 通过；本机单元 127 项通过、0 失败，5 项 Docker 专项由 Linux CI 验证。
- 使用现有 ACR 个人版拉取凭据，在真实服务器只读读取 100 条标签、下一页游标及固定镜像摘要成功。未开通企业版实例，企业版管理 API 当前通过官方 SDK 和响应契约测试，尚未使用真实企业版账号验收。

此批不改变通用 Compose 发布门禁。新标准容器交付仍需完成客户安装入口、备份恢复和服务端运行验收证据；历史部署继续使用现有路径。开发管理拆分完成，不代表通用容器交付已全部完成。
