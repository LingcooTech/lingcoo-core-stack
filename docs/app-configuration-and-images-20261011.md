# 应用配置、交付填写和图片管理

## 配置检查

应用编辑标签栏的“配置检查 X/Y”统计服务端已保存配置中通过的必要检查，不再独占卡片。点击打开明细抽屉，可从缺项直接跳到报价、套餐或交付配置。未保存修改会单独提示，不能把旧检查结果当作新配置已通过。真实支付、镜像拉取、部署恢复等在线验收单独列出，不混入配置完成度。

此检查保留服务端上架约束，前端调整不放宽正式售价、有效权益、交付清单和镜像 digest 等要求。

## 创建或编辑应用时怎样填写交付配置

1. 基本信息中选择“一键部署”，先将应用保存为草稿。免部署应用不需要填写这组配置。
2. 在“交付配置 → 交付清单来源”填写发布流程生成的 `fd-delivery.manifest.json` HTTPS 地址，保存应用，再点击“同步清单”。地址必须直接返回 JSON，不能填本机文件路径或 GitHub 文件页面。
3. 另一种来源是公开 GitHub 交付仓库：清单 URL 留空，填写仓库地址、分支/标签/提交以及相对仓库根目录的清单路径。不是要求公开业务源码。两种来源同时存在时 URL 优先。切换来源后必须先保存，否则不允许同步，避免服务端沿用旧地址。
4. 同步后，安装入口、参数、域名槽位和资产说明自动展示。平台只填写“平台预设”字段；红色星号标记必要配置。组内“已填写 X/Y”包括可选字段，仅表示已填入，保存后的配置检查才判断发布条件。
5. 保存配置，在标签栏打开配置检查，补齐报价、套餐权益及交付缺项，再切换为上架状态。同步清单本身不会自动上架，也不代表镜像已实际拉取验证。

### Retail 的具体字段来源

| 字段/内容                                        | 填写者与来源                                                                                                                                                                            |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 清单 URL                                         | 应用发布流程产出的不可变版本目录下的 `fd-delivery.manifest.json`；例如 `https://downloads.example.com/apps/lingcoo_retail_oms/<版本>/fd-delivery.manifest.json`。示例不是可用生产地址。 |
| `APP_IMAGE`                                      | 镜像发布结果中的完整 `registry/repository@sha256:<64位摘要>`，不能使用 `latest` 或猜测 digest。                                                                                         |
| `ACR_USERNAME`                                   | 平台准备的专用镜像仓库只读账号，不是 Stack 或 Retail 管理员账号。                                                                                                                       |
| `ACR_PASSWORD`                                   | 与该账号对应的受限拉取凭据。已保存时留空保留原值，页面不回显密钥。                                                                                                                      |
| `INITIAL_ADMIN_EMAIL` / `INITIAL_ADMIN_PASSWORD` | 客户创建部署时填写，不在应用的共用配置中预填。                                                                                                                                          |
| 服务器 IP、域名                                  | 自有服务器由客户在部署时提供并负责解析；托管模式由 Stack 分配服务器，客户选择子域名前缀。                                                                                               |
| 安装脚本、安装路径、域名槽位                     | 从发布后的交付清单读取，在应用仓库维护，而不是在后台重新手写一套。                                                                                                                      |

Retail 源码仓库的 `delivery/fd-delivery.manifest.json` 是构建模板，目前包含 `pending` 安装地址，不能直接当作正式发布清单使用。发布时由 `scripts/build-stack-delivery.mjs` 根据真实镜像 digest、源码 SHA 和下载目录生成 `dist/stack-delivery/fd-delivery.manifest.json`。以发布产物为准，不重新覆盖已经验收的生产配置。

完整规范继续见 `stack-app-delivery-onboarding-standard.md` 与 `retail-stack-onboarding-runbook.md`。托管还依赖已接入的托管运行配置及服务器适配器；只同步清单并不自动完成新应用的托管接入。

## 图片管理

- 应用图标、封面、截图、内容封面、文档空间图标、站点 Logo/Favicon 共用“预览 → 选择/更换 → 移除”，不再提供手填图片 URL 控件。
- 选择窗口可选取公开图片，也可上传新图片；新上传图片通过原有 S3 兼容存储流程保存并登记素材。私有素材不能直接选作公开页面图片。
- 应用详情、文章和文档正文提供“插入云存储图片”，插入当前位置并保留周边文本；富文本 Markdown 工具栏的图片命令也使用相同窗口。
- 既有图片链接继续保留和预览，不自动清空或迁移；点击“移除”只是解除当前字段引用，不删除云存储文件。正文仍可编辑 Markdown/HTML，未禁止历史外链内容。
- 图片格式仍遵循现有素材上传校验；站点图标可用 PNG，未为本次界面改动放开 SVG 等格式。
